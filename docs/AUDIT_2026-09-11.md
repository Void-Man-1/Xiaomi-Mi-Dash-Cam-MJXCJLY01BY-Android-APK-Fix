# Repository audit — 2026-09-11

Status: complete. The fixes, production deployment checks, release-integrity re-check, GitHub Actions maintenance, and stale-branch cleanup are finished.

## Executive result

The repository's release/build evidence, source-kit invariants, automation, documentation, public metadata, security posture, GitHub Pages presentation, localization, and repository hygiene were audited against the published `v2.0.0` baseline.

No defect was found in the immutable release artifact itself. The audit found maintenance issues in the repository, automation, documentation and public presentation. Those confirmed issues were fixed and then re-verified from merged `main` and the deployed GitHub Pages site. The published `v2.0.0` APK was not replaced, re-signed, retagged, or modified.

## Release and source-kit verification

The published release was downloaded independently during the audit rather than trusted from repository prose. Verification established the expected digest, package/version identity, APK signatures, certificate identity, ZIP/ELF alignment, and acceptance by the repository's own `source-kit/scripts/verify.ps1` logic.

The PowerShell source-kit scripts parse under both Windows PowerShell 5.1 and PowerShell 7. Path-containment tests rejected hostile escape cases. The stored patch payload hashes agree with the manifest. The source kit cannot perform a from-zero reconstruction using only files committed to Git because Xiaomi's original APK and selected vendor/original inputs are intentionally excluded; that is an explicit redistribution/licensing boundary documented by the project, not evidence of a broken verifier.

## Release synchronization verification

The release-sync workflow was exercised in a temporary audit workspace:

- running against the current `v2.0.0` state was idempotent;
- a simulated `v2.1.0` update changed all five GitHub Pages locales and all translated README download/version references expected by the workflow;
- the simulation did not alter the real published release.

## Website/browser verification

A staged Pages artifact was exercised in actual Google Chrome across all five locales (`en`, `pl`, `uk`, `de`, `ru`) at six viewport sizes: `360×800`, `390×844`, `768×1024`, `1024×900`, `1366×900`, and `1440×1000` — 30 locale/viewport cases in total.

The final browser pass reported `BROWSER_AUDIT_OK cases=30` and checked:

- no horizontal page or language-row overflow;
- language order `en`, `pl`, `uk`, `de`, `ru`;
- four rendered flag images with Russian text-only and Russian last;
- centered release/trust strip;
- all repository-owned page images loading from the staged site;
- three screenshot cards using uncropped `object-fit: contain` rendering;
- one playable evidence-video element per locale with metadata `576×1280` and duration above 260 seconds;
- evidence video/poster using same-origin `/media/` paths;
- the social-preview asset resolving locally at exactly `1200×630`;
- durable public-naming and repository-integrity validators passing after the browser assertions.

The audit harness was corrected during execution for two test-infrastructure mistakes (GitHub Actions shell invocation/module resolution) and one expected lazy-loading behavior. Those were not counted as product defects.

## Security and history review

The history-wide Gitleaks pass scanned 144 commits and found one candidate. Manual classification traced it to the intentionally published APK signing-certificate SHA-256 fingerprint. No private signing key, access token, password, API credential, or other reusable secret was identified by that scan.

The project continues to document that signing material, original vendor APKs, account/device data, unredacted captures, and credentials must not be committed.

## Public link review

A focused external-link pass checked 27 navigational links referenced by the README/docs and Pages `href`/`src` attributes. It found zero definitive `404`/`410` failures. Two third-party catalog links (APKFab and AppBrain) returned HTTP `403` to the GitHub runner and were retained as soft-review results rather than misclassified as broken URLs.

The production social-preview URL, which could not exist before the audit merge, was subsequently checked in the production closeout and returned HTTP 200 with the expected `1200×630` dimensions.

After the guard matched, the superseded migration, redesign, validation, language, gallery, audit, documentation-closeout, and Node-24 follow-up branches were deleted. A final GitHub branch enumeration after cleanup returned exactly one branch:

This also removes the stale-branch banner that GitHub had been surfacing for recently pushed temporary branches.

## Audit rule

A candidate was counted as a confirmed finding only when reproduced from repository state, workflow execution, release metadata, static analysis, browser behavior, or live GitHub configuration. Correct code was not rewritten for style alone, and scanner/network results were manually classified when an automated result could be a false positive or bot-block response.
